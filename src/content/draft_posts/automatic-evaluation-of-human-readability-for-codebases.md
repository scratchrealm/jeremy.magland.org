---
title: "Automatic evaluation of human readability for codebases"
---

A few years ago, software was developed and maintained by knowledgeable humans. Now it is becoming more and more common for AI agents to autonomously perform these functions. Consequently, humans are becoming less connected with codebases, and more dependent on AI to troubleshoot issues and add new features. This is dangerous! Years from now, is anyone going to be able to understand the code well enough to step in when things go awry? This is exacerbated by the increased complexity of AI-generated code. We're getting to the point where only LLMs can understand the output of LLMs!

This may not be a big deal if we assume that powerful LLMs will be available in perpetuity. But we don't know what the future will hold in this regard. At some point, it may not be practical to run these models for every routine maintainance operation. If nothing else, it's an unfortunate waste of resources to require sophisticated inference machinery for routine operations.

The solution is keeping our codebases simple enough so that ideally humans will be able to understand and maintain them into the future. This is good practice anyway. That means maintaining high quality documentation and thorough test infrastructure, but it also means manageable project size and a modular layout. These are often neglected priorities these days where frontier models can add sprawling features without the developer never looking at the code. We don't notice the problem because agents can understand it. But as I said, it's a major waste of resources, makes us dependented on massive LLMs, and in general is bad practice.

Gentl is a tool for evaluating whether a project/codebase is human developer-friendly. It uses a special LLM agent to perform basic project tasks with intentionally limited context and a work cyles that mimics the capabilities of a human developer to a degree. Rather than maintaining a massive conversation history as modern agents do (up to millions of tokens processed at every step), the gentl agent keeps a relative small notes file between steps and "forgets" all but the previous operation performed. At each turn, the agent has access to the overall goal, the working memory notes, and the previous command and output. It can then select an action (e.g., read part of a file, edit a file, run a command, etc) and receive the output. At the end of each turn it updates the working memory notes. At task completion, it self-reports whether it was successful. Then a second evaluator agent (more powerful, not mimicking a human) reviews the entire session and evaluates whether the requirements were actually met. The output report of the evaluation includes things like total tokens read (corresponding to human effort), the size of the working memory notes and points of friction. Developers can then use these to improve their codebases.
